# AGENTS.md — правила работы с Neironode

Этот файл — краткие постоянные инструкции для AI-агентов и участников проекта.

## Контекст
- Neironode — сайт небольшой IT-команды, которая принимает индивидуальные заказы на разработку и автоматизацию.
- Перед существенными изменениями ознакомься с `PROJECT.md` (продуктовые решения) и `README.md` (текущее техническое состояние).
- Главная цель сайта — понятным языком показать, чем команда может помочь, вызвать доверие и привести к прямому общению с командой.

## Разработка
- Первая версия — простой статический сайт на HTML, CSS и JavaScript без обязательного backend. Не добавляй фреймворки, базы данных или крупные зависимости без реальной необходимости и согласования.
- Предпочитай понятную структуру файлов, семантическую HTML-разметку и доступные интерактивные элементы.
- Проверяй адаптивность для телефона и компьютера, клавиатурную навигацию, читаемость и состояние ссылок.
- Избегай шаблонного AI-дизайна, перегруженных секций, бессмысленных эффектов и технического жаргона для клиентов.
- Не выдумывай заказчиков, отзывы, портфолио, статистику, гарантии, состав команды или контакты. Если данные ещё не предоставлены, обозначай место для них честно.
- Главное действие для посетителя — обсудить задачу с командой. Пока контакт не задан, не подставляй вымышленную рабочую ссылку и не имитируй функционирующую оплату.
- Учитывай, что первую версию планируется публиковать через GitHub Pages, а позже перенести на VPS.

## Проверка результата
- После изменений запускай доступные проверки. Если автоматических тестов нет, проверь хотя бы корректность файлов, навигации и отсутствие явных ошибок; честно перечисляй, что проверить не удалось.
- Не добавляй секреты, токены и пароли в репозиторий.
- Не меняй несвязанные части проекта без необходимости.

## Git и параллельная работа
- Предпочтительный процесс для задач: отдельная ветка → проверки → Pull Request → автоматическое объединение в `main`, **если** у агента есть техническая возможность, права и успешно пройдены необходимые проверки.
- Пользователю не должно требоваться вручную объединять обычные бесконфликтные изменения. Если автоматическое объединение недоступно или есть риск затереть чужую работу, сообщи об этом без утверждения, будто слияние выполнено.
- При параллельных задачах учитывай свежие изменения `main`, не делай force-push и не перезаписывай чужую работу. Конфликты сначала пытайся разрешить безопасно.
- Не публикуй недоделанные или непроверенные изменения автоматически.

## Документация
- При каждой задаче оцени, требуется ли обновить документацию:
  - `PROJECT.md` — только если изменились цель, услуги, продуктовые решения или ближайшие планы.
  - `README.md` — только если изменились технологии, структура, запуск, проверка или деплой.
  - `AGENTS.md` — только если изменились постоянные правила работы.
- Обновляй документацию в рамках той же задачи, когда это действительно нужно. Не создавай лишние документы и не веди формальный журнал каждой мелкой правки.
