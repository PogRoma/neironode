# Neironode

Сайт небольшой IT-команды: автоматизация процессов, backend-разработка, веб-приложения, API-интеграции и доработка существующих решений. Название бренда и тексты пока рабочие.

**Основное действие для посетителя:** «Обсудить проект» — перейти к прямому общению с командой. Нет корзины, регистрации и онлайн-оплаты.

## Смотреть актуальную версию

После однократного включения GitHub Pages сайт будет доступен по постоянному адресу:

**https://pogroma.github.io/neironode/**

В GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. В репозитории уже есть workflow `.github/workflows/pages.yml`, который публикует **только `site/`** после каждого push в ветку **`main`**. Страница не обязана быть опубликована сразу: результат и ошибки можно смотреть в разделе **Actions → Deploy static website to Pages**.

**Рабочий процесс:** Codex меняет `main` → GitHub Actions публикует сайт → владелец оценивает по одной ссылке → Codex дорабатывает или откатывает изменения по коммитам. Никаких обязательных feature-веток, PR или ручного merge на этапе разработки. Если конкретная облачная задача Codex технически создаёт отдельную ветку, её всё же нужно безопасно объединить с `main`, иначе опубликованный сайт не изменится.

## Стек и файлы

Статический HTML, CSS, JavaScript: без серверной базы данных, без обязательной сборки сайта и без браузерных CDN.

```text
site/index.html                # основной HTML
site/assets/css/style.css     # стили и адаптивность
site/assets/js/config.js      # название и подтверждённый Telegram-контакт
site/assets/js/main.js        # меню, навигация и появление разделов
site/assets/favicon.svg       # нейтральная типографическая иконка
.github/workflows/pages.yml    # автоматическая публикация main в Pages
preview.html                   # автономная HTML-копия для просмотра офлайн
scripts/build-preview.cjs      # генератор автономной копии
tests/site.spec.js             # браузерные тесты Playwright
AGENTS.md                     # правила для Codex
PROJECT.md                    # продуктовые решения
```

## Запуск и проверки (не требуются для обычного просмотра)

Можно открыть `site/index.html` напрямую или запустить локальный сервер Python:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory site
```

Для браузерных тестов нужен Node.js 20+ и Chromium:

```sh
npm ci
npx playwright install chromium
npm test
```

По умолчанию тесты используют системный Chromium `/usr/bin/chromium`. Для другого пути задайте `CHROMIUM_PATH=/путь/к/chromium npm test`.

Проверяются ширины 320, 375, 768 и 1440 px, отсутствие горизонтального переполнения и ошибок загрузки/JavaScript, переход к контактам, пустой и заполненный контакт, защита от некорректного URL, раскрытие услуг, мобильное меню с Escape, кликом снаружи и уходом фокуса, навигация при прокрутке и `prefers-reduced-motion`. Контент и навигация также проверяются без JavaScript, а автономная копия — без сети. Сервер для тестов запускается автоматически.

После изменения исходных файлов `site/` автономную копию можно пересобрать через `npm run build:preview`. GitHub Pages публикует исходный каталог `site/`, а не `preview.html`.

## Интерфейс

Первый экран: заголовок, короткое описание и кнопка «Обсудить проект». Пять услуг раскрываются нативными `details`, в том числе без JavaScript. Этапы работы и информация о команде оформлены текстом и разделителями; декоративных псевдокнопок нет.

Навигация закреплена при прокрутке. Мобильное меню закрывается по Escape, выбору ссылки, клику снаружи и уходу фокуса. Появление разделов отключается при `prefers-reduced-motion`; без JavaScript весь контент остаётся доступным. «Neironode» — временный текстовый wordmark, название можно заменить в конфигурации.

## Контакт и данные

Рабочее название и подтверждённый публичный Telegram username задаются в `site/assets/js/config.js`. Пока username не задан, контакт не должен выглядеть как работающая внешняя ссылка. Не придумывайте портфолио, отзывы, состав команды или достижения.

## VPS в будущем

Для Nginx или другого веб-сервера достаточно разместить содержимое `site/` в корневом каталоге сайта и настроить HTTPS. Node.js и база данных для этой статической версии не нужны.
