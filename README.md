# НЕЙРОНОД — сайт команды разработки

Первая версия русскоязычного сайта IT-услуг. «НЕЙРОНОД» — временное название.
Чистые HTML, CSS и JavaScript: без сборки, внешних шрифтов, CDN и зависимостей в браузере.

## Посмотреть без установки программ

Скачайте архив ветки и выберите **«Извлечь всё» / «Распаковать»**. Затем откройте **`preview.html` в корне распакованной папки** двойным щелчком. Это автономная копия сайта: стили, скрипты и иконка встроены в один файл. Её можно перемещать отдельно и смотреть без интернета.

Исходная версия — `site/index.html`. При открытии с диска рядом с ней должна оставаться **вся папка `site/assets/`**. Открытие HTML прямо внутри ZIP или копирование только `index.html` может показать страницу без оформления.

После изменений в `site/` обновите автономную копию (нужен Node.js):

```sh
npm run build:preview
```

`preview.html` генерируется автоматически; бренд и контакт меняйте только в исходном `site/assets/js/config.js`, затем пересоздавайте копию. GitHub Pages продолжает публиковать только `site/`.

## Локальный сервер для разработки

Нужен Python 3:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory site
```

Откройте `http://127.0.0.1:4173`. Можно также использовать `npm start`.

## Структура

```text
site/                          # только эти файлы публикуются
  index.html                   # тексты и семантическая разметка
  assets/css/style.css         # стиль и адаптивность
  assets/js/config.js          # название и Telegram-контакт
  assets/js/main.js            # контакт и мобильное меню
  assets/favicon.svg           # временный знак
.github/workflows/pages.yml    # публикация main через GitHub Actions
preview.html                   # автономная копия для просмотра
scripts/build-preview.cjs      # генератор автономной копии
playwright.config.js           # настройки браузерных проверок
tests/site.spec.js             # адаптивность и основные сценарии
```

## Бренд и контакт

Редактируйте `site/assets/js/config.js` — единственный конфигурационный файл:

- `brandName`: название, которое подставляется в шапку, подвал и заголовок вкладки.
- `telegramUsername`: подтверждённое публичное имя Telegram **без @ и без URL**. Пока оно пустое, внешняя ссылка не создаётся, сайт честно сообщает, что контакт ещё не добавлен. Некорректные значения также не активируют ссылку.

После добавления контакта проверьте, что он действительно ведёт к вашей команде. В тестах используется только перехваченная конфигурация; тестовый контакт в сайт не включён.

При окончательной смене бренда также обновите статический текст в `index.html` (резерв для отключённого JavaScript), favicon и этот README. При выключенном JavaScript весь контент и навигация доступны, но динамический Telegram-контакт не отображается.

## Контент

Все пять направлений, процесс, команда и контакты представлены на одной странице. Услуги раскрываются нативными `details`, в том числе без JavaScript. Публичных кейсов пока нет: раздел прямо сообщает об этом. Перед добавлением кейса нужны реальный проект, разрешение на публикацию и подтверждённые результаты. На сайте нет выдуманных отзывов, сотрудников или достижений.

## Проверки

Для разработки тестов: Node.js 20+ и Python 3.

```sh
npm ci
npx playwright install chromium
npm test
```

По умолчанию тесты используют `/usr/bin/chromium` в облачной среде. На другой машине укажите путь: `CHROMIUM_PATH=/путь/к/chromium npm test`. Путь к браузеру Playwright можно получить командой `node -p "require('@playwright/test').chromium.executablePath()"`.

Проверяются ширины 320, 375, 768 и 1440 px, отсутствие горизонтального переполнения и ошибок загрузки/JavaScript, CTA, пустой и заполненный контакт, защита от некорректного URL, меню с Escape, раскрытие услуг и базовая версия без JavaScript. Скриншоты сохраняются в `test-results/`. На сервере разработки тесты запускаются автоматически.

## GitHub Pages

1. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. После ревью и слияния PR в `main` workflow `Deploy static website to Pages` опубликует только каталог `site/`.
3. Проверьте завершение workflow и адрес в окружении `github-pages`. Ожидаемый адрес для этого репозитория: `https://pogroma.github.io/neironode/`.

Публикация не запускается для PR и защищена условием ветки `main`, включая ручной запуск. Относительные пути подходят для адреса проекта `/neironode/` и для корня собственного домена. Включение Pages и merge выполняет владелец репозитория; текущая реализация их не выполняет.

## Перенос на VPS

Скопируйте содержимое `site/` в document root Nginx/Caddy/Apache. Не нужен Node.js, Python, база данных или backend. Например, для Nginx задайте `root /var/www/neironode;` и `index index.html;`, затем настройте домен и HTTPS. Не публикуйте корень репозитория с тестами и служебными файлами.

Автономный `preview.html` дополнительно проверяется без сети, внешних файлов и базового URL: оформление, отсутствие запросов, мобильное меню и переход к контактам. В управляемом Chromium этой среды `file://` заблокирован политикой администратора, поэтому этот тест загружает HTML в `about:blank` через `setContent`, а не имитирует открытие файла с диска.
